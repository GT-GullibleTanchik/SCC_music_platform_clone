# 🎵 SoundCloud Clone — Музична Платформа (SPA)

Сучасний, адаптивний веб-додаток для прослуховування музики, натхненний інтерфейсом та логікою **SoundCloud** та **Spotify**. Проект реалізований як **Single Page Application (SPA)** на чистому JavaScript (Vanilla JS) без використання важких фреймворків.

## ✨ Основний функціонал (Features)

- **Повноцінний аудіоплеєр:** Відтворення, пауза, перемикання треків назад/вперед (по колу), регулювання гучності та інтерактивна перемотування треку.
- **Синхронізована звукова хвиля (Waveform):** Кастомна інтерактивна смуга прогресу у вигляді аудіо-хвилі на головному банері, яка зафарбовується в такт музиці та підтримує кліки для перемотування пісні.
- **Живий пошук (Музичний фільтр):** Миттєва фільтрація карток треків на головній сторінці за назвою пісні або іменем виконавця в режимі реального часу.
- **Система авторизації (Вхід / Реєстрація):** Модальне вікно для створення акаунтів та входу. Система повністю ізолює дані користувачів: у кожного акаунту своя унікальна бібліотека.
- **Роутинг без перезавантаження:** Навігація між сторінками «Головна» та «Бібліотека» реалізована за допомогою **Hash Routing (#home / #library)**, що дозволяє змінювати адресу в рядку браузера без переривання звуку чи скидання стану плеєра.
- **Розумна бібліотека зі складним алгоритмом синхронізації:**
  1. *Вподобані (Likes):* Додавання треків у плейліст улюблених.
  2. *Додані в бібліотеку:* Окремий список збереженої музики.
  3. *Власний список (Custom Playlist):* Користувач може вручну додавати/видаляти треки сюди, але **тільки якщо** трек є в Likes або Бібліотеці. Якщо трек видаляється з обох перших списків — він автоматично зникає з кастомного списку.

## 🛠️ Технологічний стек (Tech Stack)

- **HTML5:** Семантична розмітка, використання аудіо-елементів та кастомних `<input type="range">`.
- **CSS3:** Сучасна темна тема, Flexbox та Grid для макетів (Layout Shift Protection), плавність (`transition`), кастомні скролбари та анімації появи елементів.
- **JavaScript (ES6+):** Маніпуляція DOM-деревом, асинхронне керування медіа-потоками (`HTMLAudioElement`), обробка подій (`timeupdate`, `ended`, `input`) та збереження даних.
- **LocalStorage:** Використовується як локальна клієнтська база даних для збереження користувачів (`scc_users`) та їхніх персональних медіатек.

## 🔧 Як розгорнути проект локально

1. Склонуйте репозиторій або просто скачайте архів із файлами.
2. Відкрийте файл `index.html` у будь-якому браузері (рекомендується використовувати плагін **Live Server** у VS Code для коректної роботи аудіо-потоків).
3. Для тестування аудіо використовуються відкриті потокові MP3-посилання. Ви можете замінити масив `tracksData` в `script.js` на власні локальні файли або API.

## 📡 Інструкція для розробників: Як підключити до свого сервера (Backend Integration)

Цей проект повністю готовий до масштабування та інтеграції з сервером (Node.js / Express, Python / Django, PHP, Firebase тощо). Щоб замінити клієнтську пам'ять `LocalStorage` на реальну базу даних (наприклад, PostgreSQL або MongoDB), виконайте наступні кроки:

### 1. Заміна бази даних треків
Зараз масив `tracksData` зашитий у фронтенд. Замініть його на динамічний запит до вашого сервера за допомогою `fetch`:
```javascript
let tracksData = [];
fetch('https://your-api-server.com')
    .then(res => res.json())
    .then(data => {
        tracksData = data;
        // викликати функцію ініціалізації карток на сторінці
    });
```

### 2. Перенесення авторизації на Бекенд
У **Розділі 15** файлу `script.js` замініть перевірку масиву `localStorage.getItem('scc_users')` на відправку POST-запиту:
```javascript
// Приклад для Входу (Login)
fetch('https://your-api-server.com', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ username, password })
})
.then(res => res.json())
.then(data => {
    if (data.token) {
        currentUser = data.username;
        localStorage.setItem('scc_token', data.token); // зберігаємо JWT-токен
        // оновити UI
    }
});
```

### 3. Збереження плейлістів у БД
Замість функцій `getUserData` та `saveUserData`, які працюють з пам'яттю браузера, робіть GET та POST запити до таблиць вашої бази даних, передаючи ID користувача або його токен у заголовках (`Headers`).
